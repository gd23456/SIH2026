# Build Order — getting Karigar AI onto a phone

Read this before opening the project in Android Studio.

**The one thing to know up front:** cloning this repo and opening
`frontend/android` in Android Studio **will fail**, and the error will point at
Gradle even though Gradle is fine. [Stage 2](#stage-2--generate-what-git-does-not-carry)
explains why, and fixes it in one command.

---

## Prerequisites

| Tool | Version | Why this one |
|---|---|---|
| **JDK** | **17 or 21** | Gradle 8.9 supports Java 8–22. Android Studio 2026.1 bundles **JDK 25**, which is too new, and Homebrew's `java` is 26. Neither works. |
| Node.js | 20+ | |
| Android Studio | any recent | |
| Android SDK | API 34 platform + build-tools | Installed via Android Studio's SDK Manager |
| Python | 3.11 | Backend only — see [SETUP.md](SETUP.md) |

### Picking the right JDK in Android Studio

Android Studio usually finds a compatible JDK by itself. If the sync fails with
`Unsupported class file major version` or a Java-version complaint:

**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**

Choose a **17** or **21** entry. An older JetBrains Runtime left behind by a
previous Android Studio shows up as `jbr-21`; otherwise install Temurin 21 from
that same dropdown (*Download JDK…*).

For command-line builds, point `JAVA_HOME` at it explicitly:

```bash
# macOS, using a JetBrains Runtime 21 that Android Studio left behind
export JAVA_HOME="$HOME/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
```

## Stage 2 — Generate what git does not carry

**This is the stage everyone skips, and skipping it is why the IDE fails.**

Two things the Android project needs are **generated, not committed**:

| Path | Gitignored at | Generated by |
|---|---|---|
| `frontend/android/app/src/main/assets/public/` | `frontend/android/.gitignore` | `npx cap sync` |
| `frontend/android/capacitor-cordova-android-plugins/` | `frontend/android/.gitignore:93` | `npx cap sync` |

`settings.gradle` line 2 does `include ':capacitor-cordova-android-plugins'`, so
on a fresh clone Gradle is told to configure a module that isn't there:

```
Could not read script '.../capacitor-cordova-android-plugins/cordova.variables.gradle'
as it does not exist.
```

That reads like a broken Gradle config. It isn't — the module simply hasn't been
generated yet. And even if you get past it, an empty `assets/public/` means the
app installs and launches to a **blank white screen**, with nothing in logcat to
explain it.

```bash
cd frontend
npm run build          # web app  -> dist/
npx cap sync android   # dist/    -> android/app/src/main/assets/public/
                       #          + generates capacitor-cordova-android-plugins/
```

**Verify both:**

```bash
ls frontend/android/app/src/main/assets/public/index.html
ls frontend/android/capacitor-cordova-android-plugins/cordova.variables.gradle
```

> **Re-run `npx cap sync android` every time you change frontend code.** The
> Android project serves a *copy* of `dist/`. Editing React and hitting Run in
> Android Studio rebuilds the old bundle — a genuinely confusing hour.

## Stage 3 — Open in Android Studio

Open the **`frontend/android`** folder — not the repo root.

```bash
cd frontend && npx cap open android
```

Let the Gradle sync finish. The first one downloads Gradle 8.9 (~220MB) plus the
Android dependencies, so give it a few minutes on a decent connection.

**Verify:** sync completes with no red banner, and `app` appears in the run
configuration dropdown.

Or from the command line:

```bash
cd frontend/android && ./gradlew assembleDebug
# -> app/build/outputs/apk/debug/app-debug.apk   (~3.8MB)
```

## Stage 4 — Run it

### On your own phone

1. Enable **Developer options** → **USB debugging** (tap *Build number* 7× in
   Settings → About phone).
2. Plug in, accept the debugging prompt, pick your device in Android Studio, **Run ▶**.
3. Grant microphone and camera when asked.

### On the emulator

Any Play-Store-enabled image, API 33+. Note that **voice will not work on most
emulator images** — they ship no speech-recognition service. The text box beside
the mic is the fallback, and that is exactly why it exists. Test voice on real
hardware.

## Stage 5 — Point the app at a backend

The app needs the FastAPI backend for AI, publishing and the storefront.

```bash
cd SIH2026 && make backend    # binds 0.0.0.0:8000
make ip                       # your LAN IP, e.g. 192.168.0.12
```

| Where the app runs | Backend address |
|---|---|
| Emulator | `http://10.0.2.2:8000` — the app's default, no setup |
| Real phone | `http://<laptop-LAN-IP>:8000` |

On a real phone, set it **in the app**: the **⚙︎ Connection** screen on the
welcome page. Type the address and tap Test — it reports honestly whether the
phone can see the laptop, rather than silently falling back to demo data.

**Phone and laptop must be on the same network.** Use your phone's hotspot; most
campus and venue wifi has client isolation, which blocks phone→laptop traffic
silently.

**Verify:** open `http://<LAN-IP>:8000/api/health` **in the phone's browser**
first. If that does not return JSON, nothing else will work.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Could not read script '...cordova.variables.gradle'` | Stage 2 not run | `npx cap sync android` |
| App installs, **blank white screen** | `assets/public/` empty — Stage 2 not run | `npm run build && npx cap sync android` |
| `Unsupported class file major version` / Java version error | Gradle JDK is 25 or 26 | Set Gradle JDK to 17 or 21 |
| `SDK location not found` | No `local.properties` | Open once in Android Studio, or `echo "sdk.dir=$HOME/Library/Android/sdk" > frontend/android/local.properties` |
| Frontend edits do not appear | Android serves a copy of `dist/` | `npm run build && npx cap sync android` |
| App cannot reach the backend on a real phone | Different networks, or wrong IP | Hotspot, then ⚙︎ Connection → Test |
| Voice does nothing on the emulator | No speech service on the image | Expected. Use the text box, or test on a real phone |
| `● AI` badge says **demo** | No `GEMINI_API_KEY` | Add it to `backend/.env`. Listings and prices are canned until then |
| Google sign-in lands on the demo screen | No `VITE_FIREBASE_*` | Add them to `frontend/.env`. Expected otherwise |

## Windows

The `Makefile` assumes POSIX paths and will not run. Equivalents:

| Instead of | Run |
|---|---|
| `make setup` | `cd frontend && npm install`, then see [SETUP.md](SETUP.md) for the venv |
| `make backend` | `backend\.venv\Scripts\uvicorn app.main:app --host 0.0.0.0 --port 8000 --app-dir backend` |
| `make ip` | `ipconfig` → your IPv4 address |
| `./gradlew assembleDebug` | `gradlew.bat assembleDebug` |

## The 60-second version

```bash
git clone https://github.com/gd23456/SIH2026.git && cd SIH2026
cd frontend && npm install && npm run build && npx cap sync android
npx cap open android      # Gradle JDK must be 17 or 21
```

Then in a second terminal: `make backend`.
